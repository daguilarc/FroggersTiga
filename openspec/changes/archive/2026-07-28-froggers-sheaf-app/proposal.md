## Why

Desktop Froggers v2 spent its life re-implementing what Sheaf ships. The archived `desktop-v2-sheaf-runtime-harmonization` change tried to converge the existing JUCE/VST tree onto Sheaf incrementally; the 2026-07-25 preflight audit showed the remaining work was mostly *deletion* of a bespoke host layer (`FroggersV2ControlCore`, `HostParameterInventoryV2`, `HostParameterRoutingV2`, `DesktopHostIO`, the JUCE `MainComponent` shell) that serves neither of the two hosts Froggers actually wants: Sheaf **Runtime** (desktop, via the `sheaf-patch` launcher) and the Sheaf **browser/patcher** host.

Both hosts require exactly one thing: a type satisfying `synth::SynthApplication`. Braid 4 already is that type, and its structure — 16-slot banks, per-parameter and per-bank colors, `ScopeWriter`-fed visualizers, and a parameter-filtering seam — is the structure Froggers wants. (Modulation **drill-in** is generic `Bank` machinery that Braid reaches through the same press path; what Sheaf does *not* provide is any depth cap or level stack — see design D5/D9b.)

Equally decisive: desktop-v2 shares `src/core/` with the **Daisy firmware** and the **web host**, which is the sole cause of the flag-gating complexity (host-kind branches, retained-but-neutralized parameters, "do not touch shared infra") that dominated the previous plan. A new app owning a **copy** of the Froggers DSP shares zero files with Daisy/v1 and therefore cannot regress them.

**Guiding light: use the Sheaf classes, keep the Froggers topology.**

## What Changes

- **NEW APP.** A `SynthApplication`-conforming Froggers app is added to this repo, modeled on `Sheaf/projects/synth/apps/braid-4`, built against Sheaf as a **git submodule** (`External/Sheaf`, pinned `1940ddcb`) with its own **Makefile** — Sheaf is Makefile-only, so the build is not CMake. It registers into the `sheaf-patch` launcher through Sheaf's upstream out-of-tree app-registration hook (added at that pin), so **no file inside the submodule is modified** by this change — only the gitlink moves — and exports the browser ABI for patcher hosting.
- **Sheaf owns the model.** `ParameterManager` / `ParameterGroup` / `Bank` / `BankSlot` / `SceneState` / `ScopeWriter` / `ScopeVisualizer` replace every bespoke Froggers equivalent. Parameters are **monophonic** (`numVoices = 1`) with Froggers' value scaling.
- **Froggers owns the topology and the DSP.** VCO pitch/shape-morph/PM model, Fuegoize, Marbles, envelope followers, ResonantBump / Comb / PureDelay, and the ASR envelope are **copied** into the new app as pure DSP. `src/core/`, `sim/`, `desktop/`, `desktop-v2/`, and the Daisy firmware are **not modified**.
- **Pages become 16-slot banks, one bank per page.** Page conventions are **kept** (no merging). Slots are indexed **0–15** (0-based, matching Sheaf's physical encoder ids). In every bank, **slot index 14 is local Crispy and index 15 is global Crunchy**, fixed so neither moves when banks change; indices 0–8 hold that page's nine parameters and 9–13 render empty. The three **Shape** (VCO morph) controls stop being a separate global axis and become ordinary Audio slots. All six banks land at **9 parameters** + Crispy + Crunchy. **Each bank carries its own color.**
- **Fuegoization is re-homed onto Braid's filtering seam.** Global **Crunchy** and per-bank **Crispy** are applied via `Parameter::ProcessLitePhase1()` → `ReplaceCachedKnobValue()` → `ProcessLitePhase2()`, the same seam Braid 4 uses for its per-oscillator smoothing. The Fuegoize transform itself is Froggers' — copied from the **Daisy firmware's** implementation (`src/core/Parameter.hpp:129-151`), not from `sim/Fuegoize.hpp`, whose `:23` carries a divide-by-zero regression at high knob values (design D6).
- **Modulation slate is fixed at 15 sources + Target/Back**, matching Sheaf's `kRequiredModulatorCount = 15`: **6 Marbles-style Random S&H sources** (no source-level controls; depth encoders only) — the sixth is **not** Marbles-derived, it is a Sheaf `GangedRandomLfo` (smooth, tempo-proportional, deja-vu-immune), per design D8 — 3 VCO audio outs, 3 VCO envelope followers, Noise, then 2 external-audio sources last (marked **not connected** when no input is present: still shown, inert, rendered as disconnected, so the slate never changes size). Sheaf's `StandardModulators` aggregate is **not** used — its random count is fixed at four (design D5). **Drill-in reaches two levels; a third is refused** by an app-side level counter, and Back exits to the parameter grid from any level (Sheaf ships no level stack — design D5).
- **Randomize All and Randomize Page replace Froggers' four legacy randomize affordances** (2 global, 2 per-page, operator, 2026-07-26; refined operator, 2026-07-26), and both are now **context-sensitive by view**: "All" means wider and deeper, "Page" means exactly what is displayed. Randomize All on a **parameter page** randomizes every parameter value across all six banks — Crispy included, Crunchy excluded — plus level-1 depths only, never level 2. Randomize All on a **level-1 mod-detail grid** instead randomizes that one parameter's 15 depths and materializes-and-randomizes their 225 level-2 depths (240 total, bounded to that one parameter). Randomize Page always randomizes exactly what's displayed (values on a parameter page, 15 depths on a level-1 or level-2 grid); at level 2 the two buttons coincide, since the depth cap is 2. Sheaf remains the sole randomization mutator (`Modifier::Random`, `Bank::RandomizeModulationDepths`); the app only selects the target set and, now, the view-dependent scope (design D14). **Placement:** Randomize All keeps the existing global-strip `RandAll` position; Randomize Page restores the per-page header position desktop-v2 had removed as duplicative — sound now because the two controls' scopes genuinely differ. **Retired, not ported:** "Rand waveforms" (subsumed by Shape controls moving on-grid) and "Rand Resample" (a manual Marbles step that would fight the new clock-synced advance). **Deliberate change from v2:** Crunchy is excluded from randomization here, whereas v2's Rand All did randomize it (`desktop-v2/tests/FroggersV2AppCoreFacade_test.cpp:338,343`) — recorded so it is never "restored" as a regression fix.
- **Visualizers:** the two Braid 4 scope grids are replaced by Froggers VCO scopes (inherited for free by exposing Sheaf's VCO `UIState` shape); Marbles render their remembered-value loop as a waveform; **ResonantBump and Comb render transfer-function plots** via `DspTransferFunction::FrequencyResponse()`.
- **Marbles advance on the master clock's quarter-note pulse** (`MasterClock` transport quarter notes + `Phasor2Tick`), including external MIDI clock sync.
- **UI ports the v2 design**: the archived Layout-addendum "Candidate A" (scopes + chrome band above a 4×4/16-slot encoder grid, in-place swap to the mod-detail grid on drill-in) is re-expressed in portable `synth::ui`. The chrome band carries a **BPM slider beside the scene slider** (operator, 2026-07-26), driving Sheaf's `MasterClock` tempo.
- **Repo becomes a Sheaf package publisher.** The app (`appId` **`frogg3rs`**, publisher **`daguilarc`** — **permanent**: saved patches are addressed `daguilarc/frogg3rs`, so this identity is never changed after publication) builds to a browser package (5 artifact roles, content-hashed `buildId`) plus a schema-v1 `catalog.json`, hosted from this repo over HTTPS+CORS so Sheaf can add our catalog URL to its registry.
- **The same browser build becomes the public website.** `.github/workflows/pages.yml` currently builds `wasm/` + `web/` and deploys the old site at base `/FroggersTiga/`. It is rewritten to build and deploy the **new app** instead, with the Sheaf catalog published to a subpath of the same site in one atomic job. The legacy `web/` and `wasm/` trees are **not modified** — they simply stop being built. Deleting them belongs to the retirement change below.
- **Repository rename gated publication; the rename is done.** The repo was renamed on 2026-07-27 to **`frogg3rs`** (not `froggers3`, as this proposal originally assumed), before anything is committed, pushed, or released publicly, so the site base path (`/frogg3rs/`), the catalog URL handed to Sheaf (`https://daguilarc.github.io/frogg3rs/catalogs/daguilarc/catalog.json`), and every package artifact URL are minted once under the final name. Operator-visible product naming in the app header is unaffected.
- **Fixed to the firmware's behavior, not copied blind.** The copied fuegoize corrects a divide-by-zero present in `sim/Fuegoize.hpp:23` (UBSan-confirmed; `-O0` and `-O2` disagree). The Daisy firmware is unaffected by that defect and is the parity reference. Fixing `sim/` itself is out of scope and flagged for its own change.

## Capabilities

### New Capabilities
- `froggers-sheaf-runtime-app`: Froggers satisfies `synth::SynthApplication`; runs under Sheaf Runtime via `sheaf-patch` registration and under the browser host via `SYNTH_BROWSER_APP`.
- `froggers-sheaf-parameter-model`: monophonic Sheaf parameter/bank model; one 16-slot bank per Froggers page; fixed Crispy/Crunchy slots (indices 14/15); Shape controls on-grid; per-bank colors; scenes.
- `froggers-fuegoization`: global Crunchy + per-bank Crispy on the `ReplaceCachedKnobValue` seam, preserving the Froggers Fuegoize transform.
- `froggers-modulation-slate`: the fixed 15-source modulation slate + Target/Back cell; drill-in permitted to two levels, a third refused; Randomize All (context-sensitive: L1-only from a parameter page, but reaches L2 for one focused parameter when pressed on an L1 grid) and Randomize Page (always exactly what's displayed, and coincides with Randomize All at level 2) are the two randomize affordances.
- `froggers-vco-topology`: Froggers VCO topology (pitch, Shape morph, independent-PM) exposing Sheaf's VCO `UIState` so `ScopeVisualizer` works unmodified.
- `froggers-marbles-modulator`: six Marbles-style Random S&H sources with no source-level controls (five stepped with deja-vu loops, one smooth Y-style immune to deja-vu) advanced by the master-clock quarter-note pulse, shaped only through second-layer modulation, with remembered-loop visualizers.
- `froggers-filter-transfer-visualizers`: ResonantBump + Comb expose `DspTransferFunction`; a Sheaf-idiomatic `Visualizer` plots their frequency response.
- `froggers-app-surface-layout`: the portable Froggers surface (dual VCO scope band + chrome, 16-slot encoder grid, in-place mod-detail swap) ported from the v2 layout design.
- `froggers-browser-package`: browser build, package assembly, catalog document, and HTTPS/CORS hosting for Sheaf registry listing.
- `froggers-web-host`: the same browser build **replaces the public Froggers website**; the legacy `web/`+`wasm/` trees go dormant (unmodified, no longer built or deployed); publication is gated on the repository rename.

### Modified Capabilities
None. This change adds a parallel app; it modifies no existing capability.

## Impact

- **Code (new):** a new app tree in this repo + `External/Sheaf` submodule + browser packaging/publish tooling and CI.
- **Code (frozen, unmodified):** `desktop-v2/`, `desktop/` (v1), `src/` (incl. Daisy firmware `src/FroggersTiga/`), `sim/`, `wasm/`, `vcv/`, `web/`. The Daisy/field product is **untouched by construction** — the new app shares no source file with it.
- **Baseline caveat:** `src/FroggersTiga/build/` holds **5 tracked build artifacts** (`.bin .d .elf .map .o`), currently dirty in the working tree. The frozen-tree proof must run against a recorded baseline commit, and firmware parity must be checked as an out-of-tree output hash — building the firmware in place rewrites tracked files inside a frozen tree (task 12.4). Of the 5, only **`FroggersTiga.bin`** is build-location independent (0 absolute paths): `.elf` embeds 22, `.map` 64, and `.d` 408 occurrences of the absolute build path, so an out-of-tree rebuild changes those three hashes for path reasons alone — `.bin` is the only valid parity artifact. There is no `__DATE__`/`__TIME__` embedding anywhere under `src/`, so `.bin` is genuinely reproducible, and `BUILD_DIR ?= build` (`src/mk/config.mk:10`) is the override knob for building elsewhere.
- **DSP duplication (deliberate):** the copied Froggers DSP is a sanctioned fork, accepted to sever Daisy coupling. Recorded as a decision, not an accident.
- **OpenSpec:** supersedes and archives `desktop-v2-sheaf-runtime-harmonization` and `desktop-v2-unified-parameter-layout` (2026-07-25). `desktop-v2-external-audio-input` **must be archived as part of adopting this change** (not yet done): its entire scope was editing `desktop-v2/`, which this change freezes, so it can no longer be executed; it survives as design input for the two external-audio sources. `field-button-latency-headroom` is unrelated (Daisy).
- **Out of scope:** modifying or deleting desktop-v2, v1, `web/` or `wasm/`; stripping the `src/core/` V2 gates; fixing `sim/Fuegoize.hpp` in the frozen trees; VST/AU hosting; MIDI mapping redesign; polyphony; retiring the Daisy firmware. The first three are **deferred to the follow-ons below, not abandoned**.

## Retirement path (declared, not executed here)

This change makes the old surfaces redundant. It does **not** delete them — that is a follow-on change, so this one stays green and shippable before any deletion begins. Recording it here so "frozen" is not mistaken for "permanent".

**Follow-on A — retire the legacy desktop and web trees.** Unblocked the moment this change ships.
- Delete `desktop-v2/` and `wasm/` + `web/`.
- `desktop/CMakeLists.txt` is the **only** coupled file, and CI genuinely never builds desktop-v2 — because the whole coupling sits behind `option(BUILD_VST_V2 "..." OFF)` at `:235`, while `.github/workflows/desktop-release.yml:23-28` configures `desktop/` with default options. Inside that `if` block (`:237-305`) the couplings are: 19 UI `.cpp` at `:213-232` consumed by the `FroggersTigaPluginV2` target at `:263`; 5 further plugin `.cpp` at `:256-260`; include directories at `:269-270` and `:305`; and a test target at `:297-305`. All of that dies with `FroggersTigaPluginV2`. Separately, the IBM Plex font bundling at `:24-25`/`:32-35` is `EXISTS`-guarded, so deleting `desktop-v2/` silently drops the fonts rather than failing the build — that is the one repair that is not a deletion.
- **`FroggersTigaPluginV2` dies with the old tree** (operator, 2026-07-25).
- Drop the four now-dead helpers: `scripts/check_desktop_v2_duplicate_authority.sh`, `scripts/check_desktop_v2_layout_authority.sh`, `scripts/check_desktop_v2_operator_truth.sh`, and `scripts/open-desktop-v2.sh`.

**Follow-on B — strip the V2 gates from `src/core/`.** Unblocked only once the web host no longer consumes them, which this change accomplishes.
- Remove `m_simIndependentPm`, `m_useV2FilterParallel`, `m_v2ModTapLayout`, `UsesV2Fuego`, `SimHostKind`'s V2/Web values, the retained-but-neutralized XCPL slot, and the V2 paths in `DesktopHostIO`/`PagedHostIO`.
- **Constraint:** these gates are not scaffolding — they fork two genuinely different synths. Daisy runs the *legacy* side of every one of them (`m_simIndependentPm` defaults false at `FroggersEngine.hpp:123`; only `DesktopHostIO.hpp:331` / `PagedHostIO.hpp:82` enable it, and the firmware includes neither). Removal must delete the **V2** branches and leave Daisy's untouched, or the field product's sound changes.
- Fold in the `sim/Fuegoize.hpp:23` divide-by-zero fix (design D6) while in there.

**Follow-on C — VST/AU host (spike first, then a capability).** `FroggersTigaPluginV2`'s death is not a dead end, but this is **not** a plumbing job and should not be sized against §11's browser packaging. Browser packaging rides a complete, shipped, tested path in Sheaf; **plugin hosting has no path at all** — no `juce_add_plugin`, no `AudioProcessor`, no `createPluginFilter` anywhere in the submodule, and Sheaf builds with a Makefile rather than a JUCE-plugin CMake setup.

*Favorable:* `Engine` is device-agnostic (`Prepare(sampleRate, blockSize)` / `ProcessBlock(AudioBlock&, timestamp)`); `MasterClock` exposes `HandleExternalTransport`/`HandleExternalClock`/`ApplySyncConfig` for host sync; `juce/PortableJuceBackend.hpp` renders the portable surface independently of the standalone shell; and state serialization already exists (`include/synth/PatchPersistence.hpp`, `src/PatchPersistence.cpp`) — it may need reshaping into a host chunk, but it is not missing.

*The blocking question, to be answered by a spike before any estimate is trusted:* **modulation depth parameters are created lazily** (`src/ParameterModulation.cpp:1818,1832`, called at `:1427` and `Bank::EnsureModulationDepthParameter:2783`), whereas VST3 expects a **stable parameter set declared at instantiation**. A 15-modulator slate whose depth controls materialize only on drill-in does not map onto a fixed automation list. Resolving that — pre-materialize the full depth matrix at construction (memory/init cost, and it changes `MissingModulationDepthCount` semantics) versus expose a reduced automation surface — is the real work. A second open item: a plugin wraps `Engine`, not `Runtime<App>`, so whatever `Runtime` does besides device management (MIDI, clock wiring, persistence, UI-state pumping — `runtime/Runtime.hpp`) must be reimplemented or factored out.
