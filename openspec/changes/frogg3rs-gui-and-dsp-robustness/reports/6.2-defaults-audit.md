# 6.2 -- Default patch / registration-default audibility audit

Scope: every parameter's **registration default** (`app/FroggersParameters.hpp`'s
`FroggersBankLayouts()`), what `ApplyFroggersDefaultPatch` overlays on top of it
at startup (`app/FroggersModulation.hpp:916-963`), and the resulting **physical**
value as computed by `RouteAudioSample()` (`app/FroggersAppCore.hpp:590-727`) and
the DSP unit each knob feeds. Table covers the 9 page parameters (slots 0-8) in
each of the 6 banks -- the parameters `RouteAudioSample` actually consumes.
Crispy (slot 14) and Crunchy (slot 15) are fuego-only inputs consumed by
`ApplyFuegoSeam`/`Fuegoize`, not by `RouteAudioSample`, so they are out of this
audibility audit's scope (they warp the *other* nine knobs' cached values, they
don't independently reach the signal path).

All registration defaults below are read directly from
`app/FroggersParameters.hpp:145-184` (the only exceptions being the three Audio
pitch knobs, which this change just set to 0.2468/0.3471/0.4058 -- see the task's
primary fix).

**Finding (traced, not assumed):** `driveBlendPhase_.Process(chainIn, driveWet, blend, phase)`
(FroggersAppCore.hpp:637-638) is the *only* place `driveWet` (the entire
`FrogBlock` chain: Drive/Shape/SRR1/SRR2/XOR/BitDepth/Fuzz) reaches the output
path, and at `blend == 0.0` it returns `dry` bit-for-bit (Drive.hpp:295,
`dry*(1.0f-0.0f) + phased*0.0f == dry`). Since Blend's registration default is
0.0 and `ApplyFroggersDefaultPatch` never sets it, the design-D16 "Drive = 20%"
default patch value (FroggersModulation.hpp:958-962, confirmed live via the
passing `default_patch_drive_is_20_percent` test) has **zero audible effect**
on a freshly started app. This is a real, currently-live gap between the
default patch's stated intent and its actual output -- flagged for operator
review below, not fixed here per this task's "change exactly one thing"
constraint.

## The two required Delay/Reverb questions, answered by reading the DSP

- **Delay "Wet mix" = 0**: passes the dry (pre-delay, i.e. filter-chain) signal
  straight through. `StereoDelay::ToReverbMono` (`app/dsp/Delay.hpp:151-156`)
  computes `mix = clamp(dmix,0,1)` then returns
  `(1.0f - mix) * bumpIn + mix * monoWet` -- at `dmix == 0` this is exactly
  `bumpIn`, the un-delayed input. It is **not** a mute; it is a full dry
  pass-through of whatever signal enters the Delay stage. (In this app's
  default patch the delay engine is separately silenced by Send=0, Delay.hpp:
  105-109, so both knobs independently gate the same "off" outcome.)
- **Reverb "Wet/dry" = 0**: same shape. `Reverb::Process`'s final line
  (`app/dsp/Reverb.hpp:198-199`) is `return (1.0f - mix) * input + mix * wet;`
  -- at `mix == 0` this is exactly `input`, i.e. **fully dry**, not fully wet.
  The reverb tank (`lineA`/`lineB`/`preLine`) still runs every sample
  regardless of `mix` (it is computed unconditionally above that final line),
  it is simply never blended into the output at `mix == 0`.

## Recommended for operator review

(Recommendations only -- no code changed for any of these; only the three
Audio-bank pitch defaults were modified per this task's explicit single-change
constraint.)

1. **Drive bank Blend (slot 7) defaults to 0.0, nulling the entire Drive
   chain including the default patch's own 20% Drive setting.** Suggest
   giving Blend a nonzero registration default (e.g. 1.0, full wet) in
   `FroggersParameters.hpp`'s Drive row, mirroring how Sustain already gets a
   nonzero default at the same call site -- or, alternatively, having
   `ApplyFroggersDefaultPatch` set Blend alongside Drive (task 6.12's own
   citation already sets Drive there, FroggersModulation.hpp:958-962, but
   stops one knob short of making that setting audible). Reasoning: the
   default patch's own design intent (D16, "GAIN on the distortion page")
   is currently a complete no-op on a fresh app.
2. **Envelope Release (all three VCOs) defaults to 0.0 -> ~0.5 ms release.**
   Combined with the transport-gated ASR (D17, gate open for the first half
   of every quarter note), this makes the default patch a very short,
   percussive "tick" rather than a sustained tone. Musically valid, but
   worth confirming it matches the intended first-impression sound; a
   slightly longer default release (e.g. knob ~0.05, ~125 ms) would let the
   note ring through more of the gate-open window if a less percussive
   default is preferred.
3. **Filter bank Comb feedback (slot 4) defaults to ~-1.1 (near the most
   negative extreme of its asymmetric +-1.1 range), not 0.** It is currently
   inaudible only because Comb/Peak (slot 7) defaults to all-Peak (0). If a
   future change nudges Comb/Peak toward Comb without also revisiting Comb
   feedback, the default patch would jump straight to a near-self-oscillating
   comb. Not urgent (today's product is safe), but worth a defaultValue of a
   true-neutral feedback knob (~0.5, per `Comb::GetFeedback`'s own branch
   split at FilterFx.hpp:302) if Comb/Peak's default ever changes.
