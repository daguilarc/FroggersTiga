## ADDED Requirements

### Requirement: Web knob labels from wasm authority

The web sim UI SHALL display Audio and other page row labels from the wasm/worklet screen payload (`rows[].name` from `froggers_row_name`), not from a duplicate TypeScript label table.

#### Scenario: Audio row 7 label at runtime

- **WHEN** the web sim is on the Audio page and the worklet sends a screen update
- **THEN** knob row 7 label text is **Phase mod 3** as returned by wasm
- **AND** the label is not sourced from a hardcoded `HOST_PAGE_LABELS` array

#### Scenario: Page switch updates labels from wasm

- **WHEN** the user navigates to the Random page
- **THEN** all eight knob labels update from `rows[].name` for that page

### Requirement: Mod bay labels from shared authority

Mod bay indicator titles (VCO Envelope, Random 1 S&H, Random 2 S&H) SHALL match `ParamDisplayNames::forModSource` via wasm export or build-time generation—not hardcoded strings in `main.ts`.

#### Scenario: VCO Envelope mod bay title

- **WHEN** the mod bay renders on web
- **THEN** mod index 4 indicator title is **VCO Envelope** from the shared name table

### Requirement: Duplicate TS label table removed or generated

`web/src/main.ts` SHALL NOT maintain a hand-edited `HOST_PAGE_LABELS` matrix that mirrors `ParamDisplayNames.hpp`. If a static fallback is required before wasm ready, it SHALL be generated by script from the header.

#### Scenario: No manual HOST_PAGE_LABELS edits

- **WHEN** a developer changes Audio row 7 in `ParamDisplayNames.hpp`
- **THEN** web UI updates without editing `main.ts` label arrays (runtime wasm path or generated fallback)
